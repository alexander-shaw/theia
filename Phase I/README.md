# Phase I — Requirements Analysis and Preliminary Design

Submission index and checklist for the CptS 484 Phase I deliverables. Place completed artifacts in the directories listed below. Check items off as they are finished.

## 1. WRS Document

Location: [`wrs/`](wrs/)

Requirements:

- [ ] Issues with the preliminary definition
- [ ] Improved understanding of the problem, domain, stakeholders, and requirements
- [ ] Functional and non-functional requirements
- [ ] Relevant issue descriptions, alternatives, decisions, and rationale
- [ ] Traceability as specified in the course WRS template

## 2. Prototype and User Manual

Location: [`prototype/`](prototype/)

Requirements:

- [ ] Preliminary user interface mockups or sketches
- [ ] Descriptions of relevant interactions
- [ ] Basic user instructions aligned with the proposed scenarios

## 3. Revised Phase I Plan

Location: [`plan/`](plan/)

The current preliminary project plan is in [`../docs/CPTS-484-Preliminary-Project-Plan.pdf`](../docs/CPTS-484-Preliminary-Project-Plan.pdf). Place the revised Phase I plan in this directory.

Requirements:

- [ ] Updated preliminary project plan
- [ ] Revisions reflecting instructor feedback

## 4. AS-IS/TO-BE Presentation

Location: [`presentation/`](presentation/)

Requirements:

- [ ] Presentation slides (Phase I demo slides)
- [ ] Link to recorded presentation (unlisted YouTube; 10–15 minutes per course constraints)
- [ ] Four pairs of AS-IS/TO-BE scenarios
- [ ] Include the scenario provided in the assignment template
- [ ] Three additional pairs cover different aspects of THEIA's requirements (not the same navigation scenario repeated)
- [ ] Identify relevant features and benefiting user groups
- [ ] Identify the top-priority TO-BE scenario and include the mandatory Lesson 6 analysis

Note: Function-point calculations and creep-rate estimation are no longer required in the team presentation. Scenarios and the mock-up should remain consistent with the preliminary plan’s world assumptions (indoor room-to-room navigation, simulated beacons, emergency dial-out).

## 5. GenAI Usage and Verification Report

Location: [`ai-usage/`](ai-usage/)

Requirements:

- [ ] Document how each team member used generative AI or similar tools in producing the Phase I deliverables
- [ ] Include verification evidence as required by the course (plan constraint CO-3)

## 6. Peer Review

Every team member must complete the required peer review submission separately according to course instructions. Peer reviews are individual and are not stored as team documents in this repository.

## Submission Instructions

1. Place all required team deliverables in the `Phase I/` directory under the appropriate subdirectory.
2. Drafts may be collaborated on in Google Drive; baselined artifacts should be retained in the team GitHub repository (as stated in the preliminary project plan).
3. Record shared Drive links in the root README collaboration section when used.
4. Review the course FAQ and project specifications before finalizing the submission.
5. Commit and push the final work to the team repository.
6. Submit the final commit hash to Canvas.
7. Only one team repository submission is required; peer reviews remain individual submissions.
